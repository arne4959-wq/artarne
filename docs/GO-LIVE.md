# ก่อนเปิดให้คนทั่วไปเข้า (รายการที่ต้องใช้ข้อมูลจริงของคุณ)

รันตรวจได้ทุกเมื่อ: `npm run check` (เตือน) และ `npm run check:live` (ถ้ายังมีเตือน จะ fail ใช้ก่อนอัปโหลดจริง)

| ต้องเปลี่ยน | ที่ไหน | ทำอย่างไร |
|---|---|---|
| บัญชีรับเงินของเว็บ | `circles.js` → `CONFIG.support` | ใส่ธนาคาร (BCEL/LDB) ชื่อบัญชี เลขบัญชี และไฟล์ QR จริง แล้ว **ลบ `sample: true`** |
| อีเมลติดต่อ | `circles.js` → `CONFIG.contact` | อีเมลจริง จนกว่าจะใส่ ลิงก์ "แจ้งปัญหา" ท้ายหน้าจะถูกซ่อน (ไม่มีลิงก์ที่ไปไม่ถึง) |
| ลิงก์สนับสนุนเว็บ (ถ้ามี) | `circles.js` → `CONFIG.donate` | ลิงก์ https ของหน้าสนับสนุน เว้นว่างได้ ปุ่มจะขึ้น "เร็ว ๆ นี้" |
| นโยบายความเป็นส่วนตัว / เงื่อนไข | `privacy.html`, `terms.html` | ใส่ชื่อผู้ดำเนินการ ที่อยู่ ระยะเก็บข้อมูล แล้วลบย่อหน้า `draft` ให้ผู้รู้กฎหมายอ่านก่อน (ผมไม่ใช่ทนายความ) |
| ข้อมูลศิลปินตัวอย่าง | `artists.js` | ศิลปินตัวอย่างซ่อนได้เมื่อมีศิลปินจริงแล้ว: ตั้งตัวแปร `HIDE_DEMO` = `true` ใน GitHub (หรือ `npm run pull -- --hide-demo` ในเครื่อง) แต่ต้องใส่ id ของตัวอย่างใน `retired` ของ `published-ids.json` ก่อน (ดูหัวข้อ "ให้ศิลปินคนอื่นลงงานเอง" ท้ายไฟล์) |
| รูปตำนาน | `legends/` | `npm run pictures` |
| ภาษาลาว | `npm run lao-review` | ส่งไฟล์ที่ได้ให้เจ้าของภาษาตรวจ |
| ลิงก์แชร์ / sitemap | `node tools/build.mjs --site https://โดเมนจริง` | ใส่ URL เต็มใน og:image, canonical และสร้าง `sitemap.xml` (ตอนนี้ใช้ URL ของ GitHub Pages ถ้าเปลี่ยนโดเนมต้องรันใหม่) |
| ลิงก์ "ตั้งค่า" ท้ายหน้า | `CONFIG.manage` ใน `circles.js` | ซ่อนอยู่ (`false`) จนกว่า `manage.html` จะขึ้นจริง `npm run dist` เปิดให้เองใน `dist/` เมื่อมี `app/dist/manage.html` |
| ตาราง "เงินสนับสนุนไปไหน" | `index.html` (`.sup-led`, 3 ช่อง "ยังไม่มี") | พอเริ่มรับเงินสนับสนุน ให้ใส่ตัวเลขจริง (รับแล้ว / ใช้ไปแล้ว / คงเหลือ) และอัปเดตทุกเดือน ห้ามปล่อยให้ค้าง |
| กติกายืนยันบัญชีศิลปิน | `join.html` (ข้อความ `jn_verify`) | ข้อความบอกว่าก่อนเปิดตึกจะขอภาพหน้าจอแอปธนาคารที่เห็นชื่อบัญชี คุณต้องทำตามนี้จริง หรือแก้ข้อความให้ตรงกับวิธีที่ใช้ |

ข้อมูลตัวอย่างทั้งหมดในเว็บมีป้าย SAMPLE กำกับและ QR ตัวอย่างใช้โอนจริงไม่ได้ (ตั้งใจให้เป็นรูปแบบที่ไม่ใช่ QR จริง)

## นับคนเข้าเว็บ (ไม่บังคับ)

ปิดอยู่ตามค่าเริ่มต้น ถ้าอยากรู้ว่ามีคนเข้ากี่คน: สมัคร GoatCounter ฟรี (ไม่ใช้คุกกี้ ไม่เก็บข้อมูลส่วนตัว) แล้วใส่ `analytics: 'https://ชื่อคุณ.goatcounter.com/count'` ใน `CONFIG` ของ `circles.js` และ **ต้องแก้ `privacy.html`** ให้บอกว่ามีการนับผู้เข้าชม (ตอนนี้เขียนว่าไม่มี `npm run check` จะไม่ผ่านถ้าลืม) ระบบข้ามคนที่ตั้ง Do-Not-Track ไว้

## ตัดสินใจก่อนข้อมูลจริงเข้า (แก้ย้อนทีหลังแพง)

`npm run check` ตรวจข้อ 1–3 ให้อัตโนมัติ (FAIL ถ้าละเมิด) ส่วนข้ออื่นเป็นกติกาที่ต้องทำตาม

| เรื่อง | กติกา | ทำไม |
|---|---|---|
| ข้อมูลส่วนตัว | `artists.js` และ `artists.live.json` เป็นไฟล์สาธารณะใน repo สาธารณะ ห้ามมีอีเมลจริง เบอร์โทร หรือที่อยู่ ของส่วนตัวอยู่ใน Supabase เท่านั้น (`tools/live-data.mjs` ดึงเฉพาะคอลัมน์สาธารณะและล้างช่อง email) | พอเข้า git แล้วอยู่ในประวัติถาวร ลบไฟล์ทีหลังก็ไม่หาย |
| รูปผลงาน | ต้นฉบับไม่เข้า git เก็บที่ Supabase Storage หรือไดรฟ์ของคุณ ใน `art/` ใส่เฉพาะสำเนาเว็บ (webp/jpg ด้านยาว ≤ 1600px ไม่เกิน ~700 KB) `npm run check` เตือนไฟล์ใหญ่และล้มเมื่อเจอไฟล์ต้นฉบับ (tif, psd, raw, heic ฯลฯ) | `.git` ตอนนี้ 47 MB จากรูปตัวอย่างและ og เท่านั้น รูปจริงจะทำให้โตถาวร |
| URL ถาวร | id ของศิลปิน (และ `studio-<id>.html`, `profile-<id>.html`, `og/<id>.png`) ไม่เปลี่ยนหลังเปิดจริง รายชื่อ id ที่เปิดแล้วอยู่ใน `published-ids.json` ถ้าต้องเลิกแสดงศิลปิน ให้ใส่ใน `retired` พร้อมปลายทาง redirect ห้ามลบ | QR และลิงก์ที่แชร์ไปแล้วต้องยังเปิดได้ `npm run check` ล้มถ้า id ที่เปิดแล้วหายไป |
| การแปล | ข้อความของศิลปินใช้ภาษาที่ศิลปินเขียน (ช่องหลักตอนนี้เป็นภาษาไทย) ช่อง `...En` / `...Lo` ไม่บังคับ ถ้าไม่มี หน้าเว็บแสดงต้นฉบับ ห้ามแปลข้อความของศิลปินด้วยเครื่อง (เว็บประกาศว่า "circles ไม่แก้ไขและไม่ตีความแทน") ข้อความของเว็บเอง (ปุ่ม เมนู) ต้องมีครบสามภาษา | ศิลปิน 50 คนแปลทุกช่องสามภาษาไม่ไหว และการแปลอัตโนมัติขัดกับคำสัญญาข้างต้น |
| สิทธิ์ผลงาน | `terms.html` ข้อ 3 ระบุว่าผลงานเป็นของศิลปิน และศิลปินอนุญาตให้ circles แสดง ย่อภาพ ทำภาพตัวอย่างสำหรับแชร์ และถอนออกได้เมื่อแจ้ง | แก้เงื่อนไขทีหลังต้องขอความยินยอมศิลปินใหม่ทุกคน (ร่างนี้ต้องให้ผู้รู้กฎหมายอ่านเหมือนส่วนอื่น) |
| ป้ายที่สัญญาเป็นรายสัปดาห์ | "NEW EVERY WEEK ★", "ผลงานเด่นสัปดาห์นี้", "Artist of the week", "ไฮไลต์ประจำสัปดาห์" ก่อนเปิดจริงต้องมีคนรับผิดชอบอัปเดตทุกสัปดาห์ หรือเปลี่ยนชื่อให้ไม่สัญญาจังหวะ | ถ้าไม่มีใครอัปเดต ป้ายพวกนี้กลายเป็นหลักฐานว่าเว็บร้าง |
| ผู้ชมไทย โอนเข้าบัญชีลาว | ทดสอบจริงว่าแอปธนาคารไทยสแกน QR BCEL ได้ไหม ถ้าไม่ได้ ให้ศิลปินที่รับได้ใส่ทางสำรอง (PromptPay หรือโอนปกติ) | ถ้าสแกนไม่ได้ ผู้ชมไทยทิ้งกลางทางที่ขั้นโอน |
| ท่อ "ฉันโอนแล้ว" | หน้าโดเนทของเว็บ HTML ปัจจุบันเป็นโหมดตัวอย่างล้วน (`circles.js` ไม่เรียกฟังก์ชัน `donation-notice`) มีแต่แอป React (`app/src/lib/payment.js`) ที่ส่งการแจ้งโอนจริง ก่อนมีศิลปินจริง ต้องเลือกทาง: ย้ายขั้นนี้เข้า `circles.js` (ดึง `artist_payment`, Turnstile, ย่อสลิป, เรียกฟังก์ชัน ราว 100 บรรทัด) หรือให้หน้าโดเนทใช้แอป React | ถ้าไม่ต่อ ศิลปินจะไม่เห็นการแจ้งโอนเลย ตัดสินใจเรื่อง React vs HTML ก่อนเขียนโค้ดนี้ |
| วัดผล | เปิด GoatCounter (`CONFIG.analytics`) ตั้งแต่วันแรก และแก้ `privacy.html` ให้ตรง (`npm run check` ล้มถ้าลืม) | ข้อมูลย้อนหลังเก็บไม่ได้ |

## ให้ศิลปินจริงคนแรกรับโดเนทได้ (เริ่มจากเจ้าของเว็บ)

ตอนนี้ศิลปินตัวอย่างยังอยู่ในเว็บ (มีป้าย SAMPLE กำกับ) ส่วน Arne เป็นศิลปินจริง ตัวไม่มีช่อง `email` ใน `artists.js` ระบบจึงถือว่าเป็นของจริง: ไม่มีตัวเลข "ถูกใจ" ที่สุ่มขึ้นมาบนผลงาน และไม่ถูกจัดอันดับในหน้าไฮไลต์ ถ้าเปิดบัญชีรับเงิน กล่องโดเนทจะไม่ขึ้นป้ายสาธิตและไม่มีฟอร์มจำลอง

1. ใส่ที่ `artists.js` ในรายการของ `arne` สองช่อง: `live: true,` และ `support: {bank: 'BCEL', name: 'ชื่อบัญชีตามที่ธนาคารแสดง', no: 'เลขบัญชี', qr: 'art/qr/arne.png'},` (ข้อมูลนี้เป็นสาธารณะ เหมือนที่พิมพ์บน QR)
2. วางรูป QR ที่ `art/qr/arne.png` (ไฟล์เล็ก ไม่เกิน ~200 KB) แล้วสแกนด้วยแอปธนาคารอื่นดูก่อนว่าเข้าบัญชีถูกคน
3. ใส่ `say`, `why`, `look` (และ `sayEn`... ถ้ามี) ของผลงานทั้งสามชิ้น เพราะมีแต่เจ้าของที่เขียนได้ ถ้าไม่ใส่ หน้าต่างผลงานจะไม่มีบล็อก "ศิลปินเล่าเอง"
4. ใส่บัญชี/QR ของเว็บเอง (`CONFIG.support` ใน `circles.js` แล้วลบ `sample: true`) และอีเมลติดต่อ (`CONFIG.contact`)
5. `npm run build`, `npm run check` แล้วลองโอนจริงจำนวนน้อยหนึ่งครั้ง

หลังโอน หน้าเว็บบอกผู้โอนว่าเงินเข้าบัญชีศิลปินโดยตรงและ circles ยังไม่เก็บข้อมูลการโอน (ยังไม่มีท่อแจ้งโอน) ศิลปินเห็นยอดในแอปธนาคารของตัวเอง เมื่อต่อท่อแจ้งโอนแล้วค่อยเปลี่ยนข้อความนี้ (`real_done_p`)

## ให้ศิลปินคนอื่นลงงานเอง (ไม่ต้องแก้ `artists.js`)

ขั้นตอนเต็มอยู่ที่ `docs/SETTINGS.md` หัวข้อ "ใส่ให้ใช้งานจริง" (ข้อ ก–จ) สิ่งที่ต้องรู้ก่อนเชิญใคร:

- **ต้องตั้ง SMTP ของตัวเองก่อน** (ข้อ 3) อีเมลที่ Supabase ให้มาส่งได้เฉพาะสมาชิกทีม Supabase ของคุณ ถ้าข้าม ศิลปินจะไม่ได้รับลิงก์ล็อกอินเลย
- ถ้าตึก `arne` ไปอยู่ใน Supabase (`npm run db:seed`) ไม่ต้องทำข้อ 1–3 ของหัวข้อก่อนหน้า (แก้ `artists.js` มือ) บัญชีรับเงินและ QR กรอกเองในหน้า manage แท็บ "รับเงิน" ตึกจากฐานข้อมูลจะแทนตึกที่เขียนมือ
- ศิลปินที่เปิดตึกแล้ว ควรเพิ่ม id ใน `published-ids.json` (กันลิงก์ตาย) `npm run check` จะเตือนทุกครั้งที่เจอ id ที่ยังไม่อยู่ในรายการ
- `HIDE_DEMO` (ซ่อนศิลปินตัวอย่าง) ต้องใส่ id ของตัวอย่างใน `retired` ของ `published-ids.json` ก่อน ไม่งั้น `npm run check` ล้มและเว็บไม่ขึ้น (ตั้งใจ: ลิงก์ที่แชร์ไปแล้วต้องไม่ตายเงียบ ๆ) ลิงก์เก่าของตัวอย่างจะขึ้นหน้า "ตึกนี้ยังไม่ได้สร้าง"
- เว็บสัญญาว่าจะตรวจชื่อบัญชีก่อนเปิดตึก (ข้อความ `jn_verify`) ให้สร้างแถวศิลปินด้วย `approved = false` ก่อน แล้วค่อยเปลี่ยนเป็น `true` เมื่อตรวจแล้ว
