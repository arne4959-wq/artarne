# ระบบตั้งค่า (ให้ศิลปินแก้เอง ไม่ต้องแตะโค้ด)

หน้า **manage.html** คือห้องควบคุมของศิลปิน ล็อกอินด้วยอีเมล (ส่งลิงก์เข้าอีเมล ไม่มีรหัสผ่าน ไม่มีปุ่มสมัคร) แล้วแก้เองได้ทั้งหมดนี้:

| แท็บ | แก้อะไรได้ |
|---|---|
| โปรไฟล์ | ชื่อ 3 ภาษา, แนวงาน, เมือง, ปีที่เริ่ม, ประโยคบอกตัวตน, คอนเซ็ปต์, ประวัติ, **รูปโปรไฟล์**, **ทรง/ขนาด/สี 3 สีของตึก**, **ไทม์ไลน์**, ลิงก์ Instagram |
| งานของฉัน | เพิ่ม/แก้/ลบ/เรียงงาน, **อัปโหลดรูปงาน**, ชื่อ, ปี, วัสดุ, ขนาด, และ **คำพูดของศิลปินเอง** (งานนี้บอกอะไร / มาจากไหน / ให้ดูตรงไหน) |
| การสนับสนุน | ดูรายการที่ผู้สนับสนุนแจ้งโอน แล้วกดยืนยันหรือปฏิเสธ |
| รับเงิน | ธนาคาร เลขบัญชี QR (ที่แสดงในหน้าบริจาค) และอีเมลที่ใช้ล็อกอิน |

เว็บเป็นไฟล์นิ่ง สิ่งที่ศิลปินกดบันทึกจะอยู่ในฐานข้อมูล Supabase ก่อน แล้วขึ้นหน้าเว็บสาธารณะ **เมื่อเจ้าของเว็บดึงข้อมูลและสร้างเว็บใหม่** (ขั้นตอนข้างล่าง)

## ตั้งค่าครั้งเดียว (เจ้าของเว็บ)

ทำตาม `supabase/README.md` ข้อ "Setup" และ "Make yourself the admin" ก่อน แล้ว:

1. SQL editor → รัน `supabase/migrations/001`, `002`, `003`, `004` ตามลำดับ (ถ้ายังไม่เคยรัน) และ **`005_artist_photo.sql`** (เพิ่มช่องรูปโปรไฟล์)
2. Authentication → Users → **Send invitation** ไปที่อีเมลของคุณเอง แล้วคัดลอก user id
3. เพิ่มตึกของคุณ (id ต้องตรงกับในหน้าเว็บคือ `arne`):
   ```sql
   insert into artists (id, user_id, name, name_en, disc, city, approved)
   values ('arne', '<user id ของคุณ>', 'Arne', 'Arne', 'คอลลาจ', 'เวียงจันทน์', true);
   insert into artist_private (artist_id, email) values ('arne', 'อีเมลของคุณ');
   ```
4. เข้า `manage.html` → ใส่อีเมล → กดลิงก์ที่ส่งไป → แท็บ "งานของฉัน" เพิ่มงานพร้อมรูป (ต้องมีอย่างน้อย 1 งาน ตึกถึงจะขึ้นในเมือง)

เชิญศิลปินคนอื่นด้วยวิธีเดียวกัน (ข้อ 2 และ 3 เปลี่ยน id/ชื่อ) ไม่มีใครสมัครเองได้

## ทุกครั้งที่มีคนแก้และอยากให้ขึ้นเว็บจริง

```
npm run pull          # ดึงตึกและงานที่อนุมัติแล้วจาก Supabase ลง artists.live.json
npm run app:build     # สร้างหน้าเว็บ (รวม manage.html)
npm run dist          # รวมเป็นโฟลเดอร์ dist/ ที่ใช้อัปโหลด
```

ตึกที่มี id เดียวกับที่เขียนมือใน `artists.js` (เช่น `arne`) จะถูกแทนด้วยข้อมูลจริงจาก Supabase โดยอัตโนมัติ

## สิ่งที่ยังไม่ได้ทดสอบกับของจริง

โค้ดหน้าตั้งค่าผ่านการทดสอบด้วยฐานข้อมูลจำลอง (ล็อกอิน บันทึกโปรไฟล์ เพิ่มงาน ยืนยันการสนับสนุน) แต่ **การอัปโหลดรูปขึ้น Supabase Storage และการรัน migration 005 ยังไม่เคยทดสอบกับโปรเจกต์จริง** ลองครั้งแรกด้วยรูปเล็ก ๆ และดูว่าขึ้นในหน้าโปรไฟล์หรือไม่

## ซ่อนงานที่ถูกร้องเรียน (แอดมินเท่านั้น)

เมื่อมีคนแจ้งงานชิ้นหนึ่ง (ปุ่ม "แจ้งงานนี้" ในหน้าสตูดิโอส่งอีเมลมาที่ `CONFIG.contact` พร้อมรหัสศิลปินและลำดับงาน) ให้ซ่อนงานก่อนตรวจสอบ โดยรันใน Supabase SQL editor (ต้องรัน migration 006 ก่อน):

```sql
-- หา id ของงาน
select id, artist_id, position, title from works where artist_id = 'ใส่-id-ศิลปิน' order by position;
-- ซ่อน (true) หรือเอากลับ (false)
select admin_set_work_hidden('ใส่-uuid-ของงาน', true);
```

คนทั่วไปจะไม่เห็นงานนั้นในการ build ครั้งถัดไป (ภายในประมาณ 30 นาที) ศิลปินเจ้าของงานยังเห็นในหน้า manage พร้อมป้าย "ถูกซ่อนโดยผู้ดูแล" และปลดซ่อนเองไม่ได้
